# Step Persona Trace Reader

Use this skill to analyze one NPC at one simulation step using the **new run-scoped logging schema** (`sim_code`, `curr_step`, `sim_time`).

## When To Invoke

Invoke this skill when the user asks any of the following:

- “按 step + 人物 看全链路”
- “定位某个 NPC 在某一步为什么做了这个动作”
- “同一步里决策 -> 翻译 -> 执行 -> outcome 怎么串起来”
- “检查某个 step 有没有断链（缺日志阶段）”

Do not use this skill for legacy mixed logs that do not contain `sim_code`.

## Input Contract

Required inputs:

- `sim_code` (e.g. `sim_20260710_113627`)
- `persona` (e.g. `Maria Lopez`)
- `step` (integer, e.g. `42`)

Optional input:

- `project_root` (when running outside default repository root)

## Data Source Contract

This skill only reads logs generated by the hardened logging system. It expects records to include:

- `sim_code`
- `curr_step` (or `step` for dialogue logs)
- `sim_time`
- `persona`

Primary log files:

- `logs/perception_debug.jsonl`
- `logs/intent_memory_retrieval.jsonl`
- `logs/decision_prompt_trace.jsonl`
- `logs/translation_verify.jsonl`
- `logs/decision_stability.jsonl`
- `logs/action_execution_debug.jsonl`
- `logs/action_outcome.jsonl`
- `logs/motive_monitor.jsonl`
- `logs/step_timing.jsonl`

## Implementation Entry

Use:

- `reverie/backend_server/persona/log_analysis/step_persona_trace_reader.py`

CLI example:

```bash
python3 reverie/backend_server/persona/log_analysis/step_persona_trace_reader.py \
  --sim-code sim_20260710_113627 \
  --persona "Maria Lopez" \
  --step 42
```

## Output Contract

Return a single JSON object with:

- `timeline`: ordered stage entries (source log, event, stage, stage_order, ts/sim_time)
- `grouped`: entries grouped by source (`decision_prompt`, `translation`, `execution`, etc.)
- `decision_summary`: routed action/target/detail/reasoning
- `action_outcome_summary`: result/reason/progress_score and resolved target
- `motive_summary`: dominant/secondary motive and motive deltas
- `anchors`: `decision_ids`, `dialogue_ids`
- `missing_stages`: required chain stages that are absent
- `schema_incomplete`: whether request or records violate the new schema

## Analysis Guidance

1. Filter strictly by `sim_code + persona + curr_step`.
2. Use `stage_order` when present; otherwise use source-level fallback order.
3. Treat `decision_id` as primary chain anchor where available.
4. Flag missing required stages instead of guessing.
5. If `schema_incomplete=true`, explicitly tell the user logs are not from hardened schema.

## Quick Validation

Run:

```bash
python3 test/test_step_persona_trace_reader.py
```

Expected:

- Aggregates one complete chain for a valid `(sim_code, persona, step)`
- Ignores old-schema rows in strict mode
